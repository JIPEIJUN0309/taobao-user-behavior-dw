- 期望：`query`，实际：`query`

- DSL：`{"metrics": ["buy_uv"], "dimensions": ["user_tier"], "filters": [{"field": "user_tier", "op": "=", "value": "high"}], "time_range": {"start": "2017-11-25", "end": "2017-12-03"}, "limit": 1000}`

## 结论

**六项指标全部达标，60 题里 59 题通过（98.3%）。**

唯一失败的 A07「高活跃用户的购买用户数」：模型返回 `buy_uv` 同时带 `dimensions: [user_tier]` 和 `filters: user_tier='high'`，数值正确但多出一列，评测按列严格比对判失败。这属于**语义等价、列形状不同**，是评测口径偏严，不是模型错——留着它，是为了不让「结果一致」的定义被悄悄放宽。

**澄清命中率从 69.2% 提到 100%，靠的不是提示词。** 第一次尝试是往 prompt 里加「请谨慎、不确定就反问」，结果模型反而更倾向猜一个。真正的解法是把它变成**代码里的可判定规则**（`agent/clarify.py`），在调用模型之前判定：

| 规则 | 判定 | 例子 |
|---|---|---|
| R1 | 问题里没有任何指标说法 → 提示要求「澄清或拒答」，不抢先拦截 | 「留存怎么样」「毛利率是多少」 |
| R2 | 维度提示能唯一锁定口径 → 直接答 | 「各商品分层的加购率」只有次数口径支持 `item_tier` |
| R3 | 命中比率类泛词（转化率/加购率）→ 澄清 | 「转化率是多少」 |
| R4 | 命中环比但没提基指标 → 澄清 | 「环比怎么样」 |

两条配套判断：**只把「比率类」词的包含关系算作歧义**（「购买次数」虽然也出现在「人均购买次数」里，但没有口径之争）；**相对时间词直接拒答**（「昨天」落在数据区间之外，反问没有意义）。

规则可以离线验证：拿 60 条问题逐条比对「该澄清的是否澄清、该答的是否被误拦」，结果是 **A/B 误拦 0 条**，并已固定进测试。

代价与边界：规则是启发式的，靠这 60 条问题校准，换业务问题需要重新标定；R1 依赖模型配合提示词，还不是纯确定性。要更稳，应该把「问题里有没有指标词」升级成硬约束。
